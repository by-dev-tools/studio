# How a delay should be voiced

**Status:** open. This is an example exploration — the question is real enough to
be worth arguing about, but Onward is fictional.

## What the frames showed

| Frame | Bet | What it costs |
|---|---|---|
| A · the word | State the fact, leave the time alone | Makes you do arithmetic it already knows |
| B · revised time | Answer the real question | A revised time reads as a promise, and revisions move again |
| C · minutes late | State the size of the problem | Keeps one number, but "9 min late" is vaguer than a time |

## The tension the frames surfaced

B is the most useful and the least honest. A revised time is what you actually
want to know, and it is also the thing most likely to change again in four
minutes — at which point the board has told you two different times and been
wrong once. A and C never make that promise, and both are worse to read.

Worth noting: this is the same shape as the honesty rule in the project brief.
The unknown row keeps all three voices honest because none of them can produce a
number for it — which is a good sign that the rule is load-bearing rather than
decorative.

## Undecided

Whether B could show a revised time only once the operator marks it confirmed,
falling back to C while it is still an estimate. That is two voices in one board,
which the brief's "one number per row" rule may or may not tolerate.
